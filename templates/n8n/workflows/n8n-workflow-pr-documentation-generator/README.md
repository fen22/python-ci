# n8n PR Documentation Generator

**Status:** `draft` — workflow importable, requiere configurar GitHub App y credenciales LLM.

Workflow de n8n que se activa cuando se abre o actualiza un Pull Request en GitHub. Obtiene los archivos cambiados, llama a un LLM para generar documentación técnica estructurada (resumen, riesgos, checklist de review, recomendaciones de testing) y la publica como comentario en el PR.

## Arquitectura

```
GitHub PR Event (opened / synchronize)
    → Webhook (n8n)
    → Filtrar evento relevante
    → Extract PR Metadata
    → GitHub API: GET /pulls/{pr}/files
    → Build Context (Code node)
    → LLM API: Generate PR Documentation
    → Format Comment (Markdown)
    → GitHub API: POST /issues/{pr}/comments
```

## Requisitos previos

- n8n corriendo con webhook URL pública (o usando ngrok para pruebas locales)
- GitHub Personal Access Token con permisos: `repo` (o `pull_requests` + `contents`)
- API key de LLM (Anthropic Claude recomendado)
- Webhook configurado en el repositorio de GitHub

## Variables de entorno

| Variable | Descripción | Requerida |
|---|---|---|
| `GITHUB_TOKEN` | Personal Access Token de GitHub con permiso `repo` | Sí |
| `LLM_API_KEY` | API key del LLM | Sí |
| `LLM_MODEL` | Modelo LLM (default: `claude-3-5-sonnet-20241022`) | No |
| `LLM_API_URL` | URL del LLM (default: Anthropic) | No |

## Setup paso a paso

### 1. Importar el workflow

1. n8n → **Workflows** → **+** → **Import from file**
2. Seleccionar `src/workflow.json`
3. El workflow aparece con 9 nodos

### 2. Configurar variables de entorno en n8n

Agrega en Settings → Environment Variables:
- `GITHUB_TOKEN`: tu GitHub PAT (classic, con scope `repo`)
- `LLM_API_KEY`: tu API key de Anthropic

### 3. Activar el webhook y obtener la URL

1. Activar el workflow (toggle ON)
2. Hacer clic en el nodo **GitHub PR Webhook**
3. Copiar la **Production Webhook URL** (formato: `https://<tu-n8n>/webhook/github-pr-docs`)

### 4. Configurar el webhook en GitHub

1. En el repositorio → **Settings** → **Webhooks** → **Add webhook**
2. Payload URL: la URL copiada en el paso anterior
3. Content type: `application/json`
4. Events: seleccionar **Pull requests**
5. Active: ✓

### 5. Probar

Abre o actualiza un PR en el repositorio. En segundos, el bot publicará un comentario con la documentación generada.

**Test manual (curl):**
```bash
curl -X POST "https://<tu-n8n>/webhook-test/github-pr-docs" \
  -H "Content-Type: application/json" \
  -d @src/fixtures/pr-diff-dummy.json
```

## Personalización

- Cambiar el idioma del output: modificar el `system` prompt en el nodo "Generate PR Docs"
- Agregar contexto del repo: add another HTTP Request node to fetch `README.md` before calling the LLM
- Filtrar por label: add an IF node checking `pull_request.labels` before generating docs
- Actualizar comentario en lugar de crear uno nuevo: usar `PATCH /repos/{repo}/issues/comments/{id}` (requiere guardar el comment_id)

## Limitaciones conocidas

- El diff de archivos se trunca a 500 caracteres por archivo para evitar superar el contexto del LLM.
- No funciona con repositorios privados a menos que el GitHub Token tenga el scope adecuado.
- El workflow no detecta si ya existe un comentario generado previamente (puede crear duplicados en `synchronize`).
- Status `draft`: requiere validación con webhook real de GitHub.
